# Post (NL)

De manier waarop we software bouwen verandert op dit moment in hoog tempo. LLM's worden sneller beter, agents nemen meer taken over en skills zorgen ervoor dat steeds meer stappen in het ontwikkelproces slimmer en eenvoudiger worden. Wat een paar maanden geleden nog experimenteel voelde, is nu al onderdeel van het dagelijkse werk van veel makers en developers.

Die versnelling zie je ook duidelijk binnen het Power Platform. We bouwen niet meer alleen met losse schermen, formulieren en flows. Steeds vaker werken we aan code apps, generative experiences en Power Pages Bring Your Own Code-oplossingen. Daardoor verandert niet alleen wat we bouwen, maar ook hoe we bouwen. En als het platform sneller beweegt, dan moet de ontwikkelomgeving mee.

Daar moest ik aan denken toen ik het artikel van Felix Verduin las: Low code can be fast. Low code in an IDE is even faster. Die titel vat het eigenlijk perfect samen. Low code is al lang niet meer het alternatief voor traditioneel ontwikkelen. In veel gevallen is het juist een versneller. Maar zodra je werkt aan moderne oplossingen waarin low code en pro code samenkomen, wordt een goede IDE steeds belangrijker. Niet als extra luxe, maar als logisch onderdeel van je workflow.

Voor mij is Visual Studio Code daar op dit moment een sterk voorbeeld van. Niet alleen omdat veel developers er al dagelijks in werken, maar ook omdat VS Code zelf laat zien hoe snel tooling zich ontwikkelt. Waar het team vroeger werkte met maandelijkse releases, zie je nu een veel hoger tempo waarin nieuwe mogelijkheden sneller beschikbaar komen. Dat past precies bij deze tijd. Als AI, agents en developer workflows zich wekelijks ontwikkelen, dan wil je dat je IDE dat ritme ook aankan.

Een mooi voorbeeld daarvan is de integrated browser in VS Code. Dat klinkt misschien als een kleine feature, maar het zegt veel over de richting waarin moderne development beweegt. Je blijft in dezelfde omgeving terwijl je bouwt, test, kijkt en verbetert. Je hoeft minder te schakelen tussen editor, browser en losse tools. Dat scheelt tijd, maar vooral ook focus.

Zeker voor code apps en moderne weboplossingen binnen het Power Platform is dat relevant. Je wilt sneller zien wat er op je pagina gebeurt, makkelijker context meenemen in je werk en soepeler samenwerken met AI tijdens het bouwen. Dan wordt een geïntegreerde browser geen aardige extra, maar gewoon een heel praktische versneller.

Daar zit voor mij de kern. De toekomst van development gaat niet alleen over slimmere modellen of snellere platforms. Het gaat ook over IDE's die dat tempo kunnen volgen. En precies daarom is de ontwikkeling van Visual Studio Code zo interessant.


# Post (EN)

The way we build software is changing fast right now. LLMs are improving quickly, agents are taking on more tasks, and skills are making more and more parts of the development process smarter and easier. Things that felt experimental just a few months ago are already becoming part of the daily workflow for makers and developers.

You can see that same acceleration in the Power Platform space as well. We are no longer just building with separate screens, forms, and flows. More and more often, we are working on code apps, generative experiences, and Power Pages Bring Your Own Code solutions. That changes not only what we build, but also how we build it. And if the platform is moving faster, the development environment needs to keep up.

That was exactly what came to mind when I read Felix Verduin’s article: Low code can be fast. Low code in an IDE is even faster. That title captures it perfectly. Low code is no longer just the alternative to traditional development. In many cases, it is actually an accelerator. But as soon as you start building modern solutions where low code and pro code come together, a good IDE becomes more important. Not as a nice extra, but as a natural part of your workflow.

For me, Visual Studio Code is a strong example of that right now. Not just because so many developers already use it every day, but also because VS Code itself shows how fast tooling is evolving. Where the team used to work with monthly releases, you now see a much faster pace where new capabilities arrive more quickly. That fits this moment perfectly. If AI, agents, and developer workflows are evolving every week, then you want your IDE to keep up with that rhythm too.

A great example is the integrated browser in VS Code. It may sound like a small feature, but it says a lot about where modern development is heading. You stay in the same environment while building, testing, reviewing, and improving. You spend less time switching between your editor, browser, and other tools. That saves time, but even more importantly, it helps you stay focused.

That is especially relevant for code apps and modern web solutions in the Power Platform world. You want to see what is happening on the page faster, bring context into your work more easily, and collaborate more smoothly with AI while building. At that point, an integrated browser stops being a nice extra and becomes a very practical accelerator.

That is the core of it for me. The future of development is not only about smarter models or faster platforms. It is also about IDEs that can keep up with that speed. And that is exactly why the evolution of Visual Studio Code is so interesting.
